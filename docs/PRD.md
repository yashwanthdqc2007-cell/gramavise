# Product Requirements Document (PRD) — GRAMAVISE

**Problem Statement Code:** SIH26091  
**Project Title:** AI-Driven Hyper-Local Business Advisory and Financial Structuring Assistant for Rural Micro-Entrepreneurs  
**Document Version:** 1.0.0 (Skeleton & Foundation Phase)

---

## 1. Executive Summary

GramaVise is a decision-support platform designed to assist rural and semi-urban micro-entrepreneurs in assessing business viability, structuring bankable financial plans, matching with relevant state/central government subsidies, and receiving clear, vernacular advisory narratives.

---

## 2. Target Persona & Use Cases

### Primary Personas
1. **Rural Micro-Entrepreneur (Individual):** Kirana store owner, dairy farmer, tailor, food processing aspirant seeking ₹50,000 – ₹10,00,000 in capital.
2. **Self Help Group (SHG) / FPO Representative:** Group enterprise planning collective investment (e.g., cold storage, processing unit).
3. **Banking Correspondent / Common Service Centre (CSC) Operator:** Field agent assisting rural borrowers in preparing viable loan requests.

---

## 3. Core Functional Pillars

```text
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│ 1. Hyper-Local  │     │  2. Financial   │     │  3. Government  │     │ 4. Explainable  │
│  Geospatial &   │ ──> │   Structuring   │ ──> │ Scheme Matching │ ──> │  AI & Evidence  │
│ Market Insights │     │  & Feasibility  │     │     Engine      │     │    Advisory     │
└─────────────────┘     └─────────────────┘     └─────────────────┘     └─────────────────┘
```

### Pillar 1: Onboarding & Market Geo-Intelligence
- Capture entrepreneur profile, business category, village/block/district location, available equity, and desired loan.
- Query hyper-local business density and point-of-interest data (OSM/local indicators).

### Pillar 2: Deterministic Financial Engine
- Model initial capital breakdown (Capex + Working Capital).
- Calculate unit economics: Revenue, COGS/Variable Costs, Fixed Costs, Net Profit Margin.
- Compute Break-Even Point (Units & Revenue), EMI, and Repayment Capacity.
- Run stress tests / sensitivity checks (+/- 20% demand, price shock).

### Pillar 3: Scheme Eligibility & Subsidy Matcher
- Match business profile against schemes: PMEGP, Mudra (Shishu/Kishore/Tarun), PMFME, Stand-Up India, DAY-NRLM.
- Output estimated subsidy, required margin money, and net bank loan requirement.

### Pillar 4: Recommendation Engine & Explainable AI
- Classify verdict into deterministic statuses: `PROCEED`, `VALIDATE_FIRST`, `RECONSIDER`.
- Back every insight with an `Evidence` classification: `OBSERVED`, `CALCULATED`, `MODELLED`, `ASSUMED`, `NEEDS_VERIFICATION`.
- Generate bilingual/vernacular advisory explanation through an AI Provider.

---

## 4. Key Non-Functional Requirements
- **Determinism:** Financial calculations must never be generated by LLMs; they must be computed using hardcoded, verified Python math formulas.
- **Explainability:** No black-box advice; every recommendation links back to supporting evidence and math.
- **Modularity:** Frontend and Backend decoupled via clean OpenAPI REST specifications.
- **Offline/Low-Bandwidth Friendliness:** Lightweight JSON payloads, resilient loading states.

---

## 5. Scope & Phase Boundaries (Hackathon MVP)
- **Phase 1 (Current):** Project skeleton, type definitions, service stubs, database schema, route declarations.
- **Phase 2 (Next):** Implement mathematical formulas in Financial Engine, basic rule engine, and mock data providers.
- **Phase 3:** Integrate OSM geocoder/Overpass API, scheme matcher rules, and LLM explanation prompt.
- **Phase 4:** Connect frontend forms to backend endpoints, polish UI dashboards, and run end-to-end evaluation.
